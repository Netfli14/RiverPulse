# Подключение RiverCleaner RC-01

На сайте нет выдуманных измерений. Пока датчик не подключён, показано «—». Маркер 51.14970, 71.41830 задан вручную; он не является подтверждением фактического расположения робота. GPS из пакетов заменяет эти координаты. Последние значения становятся устаревшими через 15 секунд без нового пакета, а при разрыве BLE или WebSocket — сразу. История текущей вкладки сохраняется при повторном подключении.

## ESP32 через Bluetooth

1. Используй ESP32 с BLE: ESP32, ESP32-C3 или ESP32-S3. ESP32-S2 не имеет BLE. Прошивка использует BLE GATT, а не Bluetooth Classic SPP.
2. В Arduino IDE установи Arduino ESP32, NimBLE-Arduino 2.5.1 и ArduinoJson 7. Или используй PlatformIO конфигурацию в firmware/esp32.
3. Скопируй config.example.h в config.h. Для BLE Wi-Fi можно не настраивать.
4. Прошей riverpulse.ino. readSensors читает фактическую внутреннюю температуру ESP32. Воду, батарею, GPS и массу не подставляет: подключи драйверы именно своих датчиков, проверь единицы и калибровку, добавь соответствующие поля в readSensors.
5. В Chrome/Edge на Windows/macOS/Android открой опубликованный HTTPS сайт. Роботы → Подключить ESP32 → RiverPulse-RC-01. Держи эту вкладку открытой; обычное обновление страницы разрывает BLE. Внутренние переходы сохраняют соединение.
6. На странице появятся пакеты, реальные показатели, источник BLE и время приёма. Отсоедини ESP32: сайт должен показать разрыв соединения и устаревшие данные. Для повторного соединения снова нажми кнопку.

UUID сервиса: `7cba0001-6f4b-4a6b-8c22-f75a8af4b321`.
Телеметрия NOTIFY: `7cba0002-6f4b-4a6b-8c22-f75a8af4b321`.
Команда WRITE: `7cba0003-6f4b-4a6b-8c22-f75a8af4b321`.

Пакеты: UTF-8 JSON с завершающим LF (`\n`). Прошивка разбивает их на 20-байтовые BLE уведомления. Обязательные поля: robotId=`rc-01`, seq (целый неотрицательный). bootId меняется при перезапуске ESP32. Пример структуры ниже содержит null, а не демонстрационные измерения:

```json
{"robotId":"rc-01","bootId":"device-boot-id","seq":0,"status":"idle","battery":null,"gps":null}
```

Дополнительные поля: measuredAt (UTC ISO 8601), battery (%), speed (km/h), container (%), temperature (температура электроники, °C), waterTemperature (°C), ph, turbidity (NTU), oxygen (mg/L), conductivity (µS/cm), collectedKg (kg), gps {lat,lng}. Не пересылай неизвестные поля: строгий валидатор отвергнет неподходящий пакет.

Операторская остановка отправляет `STOP:<8-символьный-id>` и ждёт ack {id, command:"stop", ok:true}. В config.h MOTOR_ENABLE_PIN должен совпадать с enable-входом твоего драйвера. Без подключённого enable-входа прошивка возвращает ok:false. Ответ означает только подтверждение сигнала enable, а не независимую проверку вращения двигателей. Добавь физическую аварийную кнопку и аппаратный watchdog; никакой сайт не гарантирует доставку команды после потери связи. Эта прошивка не запускает движение и не реализует автономное управление.

## Сеть и постоянное хранение

В прошивке BLE-команды передаются в очередь главного цикла. Отправка HTTPS выполняется в отдельной FreeRTOS-задаче, чтобы ожидание сети не задерживало обработку STOP. Подтверждение команды сохраняется, если она пришла во время отправки предыдущего пакета. Имя устройства передаётся в scan response: оно не помещается вместе с 128-битным UUID в один рекламный пакет.

Для работы на реке: Wi-Fi ESP32 → роутер 4G/LTE → интернет. BLE используется для настройки рядом с роботом. Более эффективная схема: MQTT over TLS с QoS 1 для телеметрии → шлюз → база данных; WebRTC для видеопотока; YOLO на отдельном Raspberry Pi/ноутбуке. Vercel отвечает за интерфейс и HTTP API, а долговременный WebSocket/MQTT сервер размещается отдельно.

Реализованный HTTP путь: ESP32 отправляет пакет каждые пять секунд в `POST /api/robots/rc-01/telemetry`, с `Authorization: Bearer <ROBOT_INGEST_TOKEN>`. Сайт опрашивает сохранённый последний пакет раз в пять секунд. BLE сессия отображается локально; для просмотра с других устройств используется серверная загрузка. Нужен реальный серверный секрет минимум из 32 символов; не передавай его в браузер и не коммить config.h.

На Sites используется D1 и таблица robot_telemetry. На Vercel настрой SUPABASE_URL и SUPABASE_SERVICE_ROLE_KEY, запусти docs/supabase-telemetry.sql. RLS запрещает клиентское чтение/запись; ключ service role доступен только HTTP API. ROBOT_INGEST_TOKEN отдельный от пароля оператора. Supabase Auth для входа включается при настройке SUPABASE_URL и SUPABASE_ANON_KEY. Без настроенной настоящей базы вход завершается сообщением о недоступности, а не выдачей фиктивной сессии.

В config.h укажи WIFI_SSID, WIFI_PASSWORD, HTTPS SITE_URL и INGEST_TOKEN. ROOT_CA — реальный корневой CA цепочки TLS сертификата твоего сайта. Не отключай проверку сертификата. Для потери Wi-Fi: ESP32 переподключается; последние значения остаются помеченными как устаревшие. Облачная история записывается в таблицу; график сайта сейчас показывает до 900 принятых пакетов текущей вкладки, CSV экспортирует именно их.

Дополнительно сайт может подключиться к собственному WSS шлюзу: сообщение — один JSON пакет указанной схемы. Браузер не открывает ws:// с HTTPS страницы. Шлюз должен сам обеспечить аутентификацию и ограничения доступа.

## Камера и YOLO

Обычный ESP32 не выполняет большой YOLO-модельный инференс. ESP32-CAM можно использовать как источник MJPEG для шлюза; Raspberry Pi/ноутбук выполняет распознавание.

```bash
python3 -m venv gateways/.venv
source gateways/.venv/bin/activate
pip install -r gateways/requirements.txt
export CAMERA_SOURCE=0
export YOLO_MODEL=/absolute/path/to/your-model.pt
export SITE_ORIGINS=https://your-site.vercel.app
# Set YOLO_GATEWAY_TOKEN securely in your process manager; use 32+ characters.
uvicorn gateways.yolo_gateway:app --host 127.0.0.1 --port 8000
```

Модель должна быть обучена распознавать нужный мусор. Универсальная модель не обязана отличать каждый вид отходов. Для ESP32-CAM CAMERA_SOURCE может быть адресом его MJPEG потока внутри локальной сети. Предоставь шлюзу HTTPS через собственный сертификат/прокси или защищённый туннель. Прямой HTTP адрес ESP32 с HTTPS сайта блокируется браузером как mixed content.

Сайт: Роботы → Камера робота → HTTPS адрес `https://your-gateway/video` → токен шлюза → подключение. Для комплектного шлюза сайт запрашивает короткоживущий ticket с Bearer-токеном и затем открывает видео. Сам секрет не помещается в URL. Видео содержит рамки на тех же кадрах, которые обработала YOLO. Отдельный /detections возвращает свежие результаты для списка; сайт не накладывает их на случайный последующий кадр.

Для камеры ноутбука: Камера устройства → Разрешить камеру → HTTPS адрес шлюза и токен → Получать результаты YOLO. JPEG кадров отправляются только после включения этого переключателя в POST /detect. Не включай его, если не хочешь передавать кадры на указанный шлюз. Токен не сохраняется в localStorage. Кнопка отключения останавливает все MediaStream tracks.

## Google Maps

Без ключа сайт открывает настоящую встроенную карту Google с одной координатной точкой. Для полной Google Maps JavaScript API настрой NEXT_PUBLIC_GOOGLE_MAPS_API_KEY и необязательный NEXT_PUBLIC_GOOGLE_MAPS_MAP_ID. Ключ ограничь HTTP-referrer доменами сайта и Maps JavaScript API, включи необходимый API в Google Cloud. Billing/доступ настраивает владелец Google Cloud. При недоступном API показывается встроенная Google Maps, без локально нарисованной карты.

## Проверка с физическим оборудованием

- Прошивка действительно рекламирует сервис, BLE notifications поступают, seq увеличивается.
- Известное контрольное измерение датчика совпадает на устройстве и сайте.
- Перезапуск ESP32 меняет bootId и новый seq принимается.
- Потеря BLE/Wi-Fi обозначается на сайте; старое значение не становится новым.
- GPS переносит единственный маркер; без GPS остаётся заданная точка.
- Реальная камера показывает живой кадр. Закрытие доступа/потеря шлюза убирает результаты YOLO.
- Операторская остановка подтверждается ack, проверка выполняется с мотором в безопасном состоянии.
